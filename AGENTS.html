# 项目说明

这是电子科技大学 Data Intelligence Group（DIG, diggers.ai）的实验室官网源码，使用 VuePress 1.5.0 构建，支持英文 / 与中文 /zh/ 两套路由。

项目没有独立的 src/ 业务代码；“源码”主要是 Markdown 页面、.vuepress/config.js 站点配置和 .vuepress/public/ 静态资源。

# 常用命令

# 安装依赖（项目有 yarn.lock，优先使用 yarn）
yarn install

# 本地开发
yarn docs:dev

# 构建
yarn docs:build
# 部分脚本/CI 也使用 npm
npm run docs:build
  • 使用 yarn 管理依赖；除非确实需要，不要生成或提交 package-lock.json。
  • 不要手动修改或提交 .vuepress/dist/、node_modules/、.tmp/ 等生成物或临时目录。

# 成员页面编辑规则

# 中英文必须同步

people/README.md 与 zh/people/README.md 当前逐字节相同，中文页面尚未真正本地化。任何成员新增、删除、修改都必须同步修改两个文件，避免产生差异。

# 页面分区

成员页面从上到下依次为：

  1. ## Faculty
  2. ## Postdocs
  3. ## RA
  4. ## Ph.D. Students
  5. ## Master Students
  6. ## Undergraduate Students
  7. ## Alumni

在读成员使用卡片形式：

<div class="column">
    <img src="/src/people/xxx.jpg">
    <div>First Last (中文名)</div>
    <a href="mailto:xxx@example.com">xxx@example.com</a>
    <div>Research Direction</div>
</div>
  • 邮箱缺失：删除整个 <a href="mailto:..."> 行。
  • 研究方向缺失：删除方向 <div> 行。
  • 头像缺失：使用 /src/people/default.jpg。
  • 头像文件名应使用全小写姓名拼音，例如 lizhicheng.jpg，不要使用中文文件名。
  • 成员卡片会由页面脚本按 <img src> 的字母序自动排序，因此不需要手写字母顺序，但仍应放入正确的年级注释区块，例如 <!-- 26级 -->。
  • 删除人员时优先用 HTML 注释保留原卡片，不要直接删除，除非用户明确要求删除。

Alumni 使用 Markdown 列表：

* **First Last (中文名)**, 2023-2026, Master Student, Destination
  • 去向缺失时保留到原身份字段即可，不要写入“MISSING”等占位文本。
  • 删除 Alumni 条目时也应遵守“默认注释保留、明确要求才删除”的原则。

# 头像规则

  • 头像统一存放在 .vuepress/public/src/people/。
  • 所有新头像必须处理为 450 × 600 像素，保持 3:4 竖版比例。
  • 来源照片如果比例不是 3:4，应居中裁切或等比缩放后再保存，避免拉伸变形。
  • 使用 JPEG 保存，质量 90 左右；PNG 原图也建议转为 JPEG，背景透明部分先用白色垫底。
  • 没有真实照片的成员使用 default.jpg（450×600 占位头像），不要留下空 src。

# 临时素材与人员数据

.tmp/ 是临时工作区，通常包含：

  • 成员登记表 .xlsx（姓名、身份、邮箱、研究方向、内嵌照片）
  • 名单截图 .png
  • 学生照片压缩包 .zip

处理流程：

  1. 从 xlsx 中提取内嵌照片，并依据工作表锚定关系确认照片与人员的对应关系。
  2. 从 zip 中查找截图名单中每个人的头像。
  3. 如果邮箱或研究方向未提供，保持空白（删除对应行），不要自行推测。
  4. 将头像统一处理为 450×600 后放入 .vuepress/public/src/people/。
  5. 同步更新 people/README.md 与 zh/people/README.md。
  6. 不提交 .tmp/ 中的原始素材。

# 构建与部署

  • 依赖安装：yarn install。
  • 本地构建：yarn docs:build。
  • 构建产物：.vuepress/dist/，已加入 .gitignore，不要提交。
  • GitHub Actions 在 push 到 master 时自动构建，并发布到 diggerslab/diggerslab.github.io（CNAME 为 diggers.ai）。
  • deploy.sh 是本地手动部署脚本，包含 force push，除非用户明确要求，否则不要运行。
  • 修改成员页面后至少执行一次构建，确认没有 Markdown/HTML 结构错误。

# Codex 工作方式

  • 涉及大量文件检索、搜索、日志分析、网页抓取或需要读取大量原始内容时，优先交给 qwen 子代理完成。
  • 主 Agent 负责方案判断、最终编辑和验收，不要代替 qwen 读取大段原始材料。
  • 修改前先让 qwen 精确定位目标行并返回必要的上下文；修改完成后再次验证中英文页面是否一致、头像尺寸是否正确。

# Git

  • 当前默认分支为 master。
  • 应提交的内容通常包括：Markdown 页面、成员头像、项目配置；不要提交 node_modules/、.vuepress/dist/、.tmp/、日志和编辑器文件。
  • 未经用户明确要求，不要自动 commit、push、合并或执行 git reset、force push。
